# 想定質問カタログ（定番 × ラウンド種別 × 企業タイプ）

`prep-interview` と `scripts/interview_brief.py` が「相手から聞かれること」の下敷きに使う
**一般論のカタログ**です。見出しは `round_type` の語彙と一致させてあります（スクリプトが引くため、
`## <round_type> — …` の形を変えないこと）。

> ⚠️ **一般論であって、その企業が聞くとは限りません。** 案件固有の質問は、提出した CV・
> 企業メッセージ・案件のギャップから `interview_brief.py` が自動生成します。ここは
> 「取りこぼしを防ぐ網」として使ってください。
>
> 回答は常に `data/career.*.yaml` の事実の範囲で。裏付けの無いことは**「やっていません」と言い、
> 何が近いか**を添える — 盛らないことが最大の防御です（リファレンスチェックで必ず露見する）。

---

## 共通の定番（どのラウンドでも出うる）

- なぜ転職を考えているのか（**現職の不満をそのまま言わない**。次に何をしたいかへ変換する）
- なぜこの会社か / なぜこのポジションか（企業メッセージの `strong` 項目と自分の実績の接点で語る）
- 自己紹介を 2〜3 分で（提出した CV の順番と揃える）
- 強みと弱み（弱みは「対処している具体策」とセット。致命傷になる弱みを選ばない）
- これまでで一番苦労した仕事と、その乗り越え方
- 3〜5 年後にどうなっていたいか（`positioning.md` の狙う形と矛盾させない）
- 他社の選考状況・入社可能時期・希望条件
- 逆質問はありますか（**必ず用意する**。無いは「興味が薄い」と読まれる）

---

## `casual` — カジュアル面談

- 今日はどういう話を聞きたいですか（**主導権が来る**。聞きたいことを 3 つ用意しておく）
- 今どんなことをされていますか（3 分の概要。深掘りは相手の反応を見てから）
- 転職はどのくらい本気ですか / いつ頃を考えていますか
- どんな環境だと力を発揮できますか
- （相手からの説明が長い場合）ここまでで気になった点はありますか

## `first` — 一次（現場・実務）

- 現在の業務の一日の流れ / 担当範囲はどこからどこまでか
- （CV の実績を指して）これは具体的に何をどう進めたのか、判断はどこにあったか
- トラブル対応の実例。切り分けの順番と、判断を誤ったときにどう戻したか
- 一人で回している範囲と、他部署・ベンダーに任せている範囲
- 優先順位はどう決めているか（同時に複数降ってきたとき）
- 未経験の領域に当たったときの学び方
- 使っているツール・技術と、それを選んだ理由

## `technical` — 技術・実技

- （出題）この課題をどう進めるか、まず前提を確認してよいか
- 過去の設計判断とトレードオフ（なぜその構成にしたか、他案は何か）
- 自動化・スクリプトの保守性をどう担保しているか
- セキュリティ／権限設計で気をつけていること
- 分からないことに当たったときの調べ方・詰まったときの相談の仕方

## `manager` — 部門長・ハイアリングマネージャー

- このポジションに何を期待されていると思うか（**レベリングの確認**）
- 予算・ベンダー折衝の経験と、決裁をどう通したか
- 上長とはどう仕事をしたいか（報告の頻度・粒度）
- 人を持つ意思はあるか / 逆に持たない前提でよいか
- 入社後 90 日で何から手を付けるか（企業調査と JD からの仮説でよい。断定はしない）
- 現職で変えられなかったこと、その理由

## `executive` — 役員・最終

- 当社の事業をどう理解しているか / どこに可能性と課題を感じるか
- （企業メッセージについて）当社のバリューで最も共感するものは（**復唱しない**。
  `strength: strong` の項目を自分の実績と結び付けて語る。裏付けの無い項目は選ばない）
- 何を大事に働いているか
- 当社で 5 年後に何をしていたいか
- （圧をかける形で）当社より条件の良い会社があったらどうするか

## `hr` — 人事・条件面

- 転職理由をもう一度、時系列で
- 現在の年収の内訳（基本給 / 賞与 / みなし残業 / 手当）と希望額の根拠
- 他社の選考状況と、当社の優先度
- 入社可能日 / 有給消化 / 引き継ぎ期間
- 転勤・残業・オンコールの可否
- 健康面や就業に影響する事情の有無（**答える義務のない範囲は無理に答えない**）

## `reference` — リファレンスチェック

- （推薦者へ）一緒に働いた期間と関係性、担当範囲、強みと課題、再び一緒に働きたいか
- （本人へ）誰に依頼できるか、その人は何を語れるか
- **CV の記述と証言が食い違わないこと**が全て。`strength` の上限を守っていれば怖くない

## `offer` — オファー面談

- 条件面で気になる点はあるか / 迷っている点は何か
- いつまでに返事をもらえるか
- 他社と比較しているポイントは何か
- （こちらから）確認チェックリストの**未確認項目を全部潰す最後の機会**。
  口頭で済ませず、書面（労働条件通知書）で確認する

## 企業タイプ別に特に出やすい質問

- **外資系（日本拠点小規模）** — 英語での業務経験（読み書き・会議）／本国・APAC とのやり取りの実例／
  リモートの上司の下で自走した経験／一人で意思決定した範囲
- **日系大手** — 転職回数と各社の在籍理由／組織の中での立ち回り／年上の部下・年下の上司への対応／
  異動や職種変更への許容度
- **SaaS / スタートアップ** — 仕組みが無い状態で何を作ったか／優先順位が頻繁に変わることへの耐性／
  バリューに沿った行動をした具体例／事業数値への関心
- **SIer / 受託** — 常駐可否と範囲／客先での折衝経験／稼働の柔軟性／複数案件の同時進行
- **製造業** — 現場（工場）との折衝経験／止められない業務への配慮／レガシー環境での運用経験
- **金融・規制産業** — 統制・監査対応の経験／変更管理の手順を守った実例／オンコール経験と可否／
  情報の取り扱いルールへの適応
- **コンサル** — ケース（構造化して話す）／クライアントの反対をどう扱ったか／稼働の許容度
