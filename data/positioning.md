# ポジショニング / キャリア方針（Positioning）

> **このファイルの役割**: `vet-opportunity`・`find-opportunities`・`tailor-cv` などの Skill が
> 「分析・カスタマイズの軸」として最初に読む文書です。**あなた自身の軸**を書いてください。
> ここが具体的なほど、案件の取捨選択・CV のカスタマイズ・エージェントへの条件登録の精度が上がります。
>
> **以下はサンプル人物（山田 太郎）の記入例**です。各セクションの意図に沿って自分の言葉に書き換えてください。
> `setup-profile` スキルを使うと、対話でこの文書の下書きを作れます。

## 志望ポジション（Target）
狙う職種と「形（役割の構造）」を書く。肩書きだけでなく、日々何をする席かを具体的に。

- **狙う形**: 少人数で IT 機能をハンズオンに回すコーポレートIT／情報システム。運用・セキュリティ・
  自動化を一人称で担い、仕組みを作って属人化を減らす席。肩書きは Corporate IT / 情報システム /
  IT マネージャー など。
- **相性が良い場**: SaaS 中心のモダンな IT 環境。製造業のバックグラウンドが活きるものづくり系も可。
  5〜50 人規模でフラットな組織。
- **レベル感**: 部下 0〜数名。大規模な人管理よりも、手を動かして機能を持つ側でいたい。

## ポジショニング（Positioning）
一言で「自分は何ができる人か」。市場で自分をどう位置づけるか。

例: 「事業会社の IT 機能をまるごと持ち、運用・セキュリティ・自動化を一人称で回せる人材。SaaS
中心のモダンな環境の設計・運用に強い。」

## 差別化（Differentiators）
他の候補者と差がつく強み。3〜5 個、具体的な根拠とセットで。

1. **セキュリティ運用**: ISMS の枠組みに沿った日常運用、EDR、脆弱性・インシデント対応。
2. **自動化**: ノーコード（n8n / GAS）＋ API 連携で手作業を削減した実績。
3. **業務システム習熟**: ERP／SFA の導入支援・ユーザーサポート・ベンダー折衝。
4. **日英バイリンガル**（例: TOEIC 850）。

## 得意・不得意（人と仕事の相性）
面接・案件選びの前提になる、自分の働き方の特性。正直に書くほど後で効く。

- **得意・エネルギーが湧く**: 設計・実装・自動化そのもの。目的の明確なベンダー交渉。
- **苦手・避けたい**: 曖昧な社内政治。日々の細かい進捗管理だけの役割。

## 報酬観（Compensation anchor）
下限・目標を書く。エージェントへの条件登録や案件の足切りに使う。

例: **下限 〇〇〇万／目標 〇〇〇万**。（現職水準を下回る案件は原則見送り、など自分のルールを明記）

## 必ず確認すべき制約（Must-check）
案件ごとに面接・エージェントで必ず確認したい点。自分の弱点や譲れない条件から逆算する。

- 未経験ドメインの橋渡し方（例: 規制産業での統制運用経験として翻訳できるか）。
- 働き方（残業・通勤・リモート）の実態。
- 使用できるツール・AI 環境のポリシー。

## 避けたい／注意（Dealbreakers）
これに当てはまる席は原則見送る、という条件。`find-opportunities` はここでフィルタする。

- （例）人管理・調整が主務で、手を動かす余地が小さい席。
- （例）ヘルプデスク専任など、目指すレベルより明確に下（意図的な踏み台でない限り）。
- （例）通勤負荷が過大／残業が構造的に多い席。

## 判断軸（Decision Axis）
最終的に「受けるか／見送るか」を決める、たった一つの問い。

例: 「受かるか」でも「肩書きが上がるか」でもなく、**「この席で自分の強みを伸ばし続けられるか」**。
