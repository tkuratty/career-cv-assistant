# エージェント・紹介会社との付き合い方（方針）

> **このファイルの役割**: `vet-agent` スキルが「登録・調査・面談設計の軸」として読む文書です。
> [[positioning]] が**案件の判断軸**であるのに対し、こちらは**仲介者との関係の判断軸**。
> 以下は一般的に有効な原則をまとめたテンプレートです。金額・具体例など **〈…〉** の箇所を
> 自分の状況に合わせて書き換えてください。

## 前提：利害はどこにあるか
エージェントは多くの場合**企業側から成功報酬**を受け取る。つまり構造的に「決めさせること」に
利害があり、候補者にとっての**最適な選択**とは一致しない場面がある。敵ではないが、**代理人ではない**。
この非対称性を理解した上で付き合う。

## 最優先の制約：時間
在職中の転職活動では、**最も希少な資源は可処分時間**であることが多い。年収でも選択肢の数でもない。
したがって「情報量を最大化する」のではなく **「筋の悪い選択肢を早く捨てる」**ことに面談時間を使う。

- ポジションが曖昧なままの面談は**回数を絞る**。具体化しなければ条件登録だけ残して打ち切る。
- 面談は時間を決めて延長しない。持ち帰って判断する。
- 「まず会いましょう」に無条件では応じない。**事前に案件の具体性を確認**してから受ける。

## 原則

### 1. 「この人は誰の代理人か」を最初に確定する
- **両面型**（企業側も担当）か**片面型**（候補者側のみ）か。両面型なら企業の内部事情を直接引ける。
- 企業と**直接取引**か、**二次請け**か。二次請けは情報が劣化し、条件交渉力も落ちる。
- そのエージェント／媒体の**ビジネスモデル**（人材紹介か、掲載課金のプラットフォームか）。
  ここを間違えると期待値を誤る（例：ダイレクト応募型の媒体に選考支援を期待しない）。

### 2. 下限は早期に開示し、上限は自分から言わない
時間が希少なので**相場探りより足切りを優先**する。
- **下限は〈現職水準を超える額〉**に置く。現職を下回る／横ばいの額を下限にすると、
  転職する理由のない案件が正規の候補として流入する。
- **下限として言った額は、そのまま"着地させにいく目標値"として扱われる**前提で設定する。
- **残業時間・通勤圏を年収と同格の条件として最初に伝える**。年収が上がっても働き方が悪化する
  案件は主目的を裏切ることがある。

### 3. 肩書きではなく「形」で条件登録する
求人票の職種名で探させると外れやすい。**役割の構造で伝える**（[[positioning]] の「狙う形」を使う）。
避けたい形（[[positioning]] の dealbreakers）も**同じ具体度で**伝える。

### 4. 経歴は自分が正本を持つ。脚色させない
- 提出物は `cv/output/` の生成物のみ。エージェントによる**勝手な要約・言い換えを許可しない**。
- 事実を超える表現（例: 実態以上の役職・専任表現）は面接で崩れ、こちらが損をする。訂正する。
- 職務経歴書を渡す前に、**どの企業に出すかを事前に必ず確認する**。無断推薦を明示的に禁じる。

### 5. 重複応募を作らない
同一企業に複数経路（別エージェント／直応募）で応募すると、**選考から外される**ことがある。
- どのエージェントにどの企業を預けたかを `agents/<slug>.md` の front-matter で追跡する。
- 新しい案件を提案されたら、**まず既存の預け先と衝突しないか確認**してから受ける。

### 6. 見送っても関係は切らない
断るときは**理由と希望像をセットで**返す。次の紹介の精度が上がり、条件登録が更新される。

### 7. エージェント自体を評価して蓄積する
一度きりの取引ではなく**パイプライン**として扱う。案件単位の当たり外れではなく、
**そのエージェントが自分の"形"を理解したか**で継続を判断する。

## エージェントの評価軸（継続 / 距離を置く）
| 観点 | 継続する兆候 | 距離を置く兆候 |
| --- | --- | --- |
| 案件の具体性 | ポジション・レンジ・体制を先に出す | 「詳細は面談で」を繰り返す |
| 理解 | 「形」で提案してくる（肩書き非依存） | 職種名の一致だけで大量に送ってくる |
| 情報 | 企業の内部事情・懸念も話す | 良い面しか言わない／逆質問に答えられない |
| 誠実さ | 合わない案件を自分から取り下げる | 応募を急かす |
| 経歴の扱い | 事前確認・原文尊重 | 無断推薦／勝手な要約・脚色 |
| 領域 | 志望ドメインの実績がある | 職種名だけで領域を無視 |

## 面談で必ず確認すること（Must-ask）
1. **素性**：両面型か／企業と直接取引か／その企業への紹介実績
2. **案件の実在**：提案ポジションは実在の欠員か（増員・欠員補充の背景）／レベリング
3. **レンジ**：想定年収と内訳（賞与・みなし残業の有無）
4. **こちらの条件登録**：形（[[positioning]]）／下限・目標／残業／通勤圏／ドメイン
5. **経歴の取り扱い**：無断推薦の禁止、脚色の禁止
6. **次アクション**：いつまでに何が返ってくるか

## 開示していい情報 / しない情報
- **開示する**：職務経歴（`cv/output/` の生成物）、希望条件、転職の主動機、時間軸。
- **慎重に**：現職の年収（レンジで足りる）、他社の選考状況（急かす材料にされる）。
- **開示しない**：現職の非公開情報、社内システムの詳細、同僚の情報。
